# GPT 结构化属性自动核查与人工复核记录

> 状态：本记录对应旧的全字段人工审核方案，已被 `09_MINIMAL_CORE_TEXT_POLICY.md` 的最小核心属性自动筛选方案取代。v3 不再要求人工逐项核查 shape/background/contrast。

## 1. 目的与边界

本轮工作为 Experiment 2 的正确文本条件 `C` 建立可追溯的质量门控，先核查 GPT 文本中可以由训练 GT 验证的字段，再把无法可靠自动判断的样本交给人工复核。本轮不训练模型，也不使用测试集 GT 生成文本或 prompt。

- 数据集：IRSTD-1k、NUAA-SIRST、NUDT-SIRST 的训练划分；按此前约定不处理 NUST-SIRST。
- 审核对象：模型实际送入 CLIP 的逐图固定文本。
- 源文件：每个数据集的 `gpt5p6_clip_token_features.pt`，全程只读；输出目录保存 SHA-256 清单。
- 重要限制：服务器未保留原始 GPT 结构化 JSON、生成日志和 GPT 自报置信度。因此，本轮通过 CLIP token IDs 无损恢复实际固定文本，并重建其中可解析的字段；GPT 自报置信度不可恢复，保持为空，不做推测。
- GT 用途：只用于训练集离线审计和 teacher 质量门控，不能进入部署推理路径。

## 2. 字段级核查协议

| 字段 | 自动证据 | 自动结论的使用方式 |
|---|---|---|
| presence | mask 是否存在前景 | 可直接判定；冲突样本阻断其余目标字段 |
| count | mask 的 8 邻域连通域数 | 可直接判定，但应人工检查疑似粘连、碎片和标注问题 |
| location | 连通域中心对应 3×3 区域 | 靠近分区边界标记为 `uncertain` |
| size | 原图连通域面积，`<=25 px` 为 tiny | 可自动筛查；混合尺寸或边界情形人工确认 |
| shape | mask 几何启发式 | 仅低权重提示，不能替代人工语义判断 |
| contrast | 目标与局部环形背景的灰度 SCR 启发式 | 仅低权重提示，不能等同 GPT 语义真值 |
| background | 无对应 GT 语义标注 | 全部保持 `unverified`，依赖人工检查 |

样本级自动状态：

- `objective_pass`：presence、count、location、size 等客观字段未发现冲突；
- `partial_auto`：存在边界不确定、背景未验证或低权重启发式问题；
- `reject_auto`：presence 冲突，禁止直接作为正确文本条件 `C`，也不进入人工审核队列；仅保留在自动拒绝清单和完整审计记录中。

客观冲突字段在人工确认前权重设为 0；`shape`、`contrast` 只赋低权重；`background` 在人工确认前权重为 0。该设计允许后续采用分字段 token/role embedding，而不是把整句文本压成不可隔离错误的单个全局向量。

## 3. 自动核查结果

共核查 1,676 张训练图像，缺失 0 张。

| 数据集 | 核查数 | objective pass | partial auto | reject auto | 旧版完整复核队列 |
|---|---:|---:|---:|---:|---:|
| IRSTD-1k | 800 | 53 | 708 | 39 | 672 |
| NUAA-SIRST | 213 | 17 | 189 | 7 | 149 |
| NUDT-SIRST | 663 | 94 | 504 | 65 | 507 |
| 合计 | 1,676 | 164 | 1,401 | 111 | 1,328 |

关键客观字段的自动冲突数如下。位置字段另有大量边界不确定样本，不能简单并入错误率。

| 数据集 | presence 冲突 | count 冲突 | location 冲突 | size 冲突 |
|---|---:|---:|---:|---:|
| IRSTD-1k | 39 | 131 | 72 | 446 |
| NUAA-SIRST | 7 | 14 | 26 | 77 |
| NUDT-SIRST | 65 | 96 | 82 | 229 |

其中 presence 自动冲突率分别约为 4.9%、3.3% 和 9.8%。该结果说明 GPT 固定文本不能未经筛查就全部视为正确条件 `C`；尤其是位置、尺寸、形状和背景字段，应采用字段级可信度、mask 或人工修订，而不是整句全收或全弃。

以上是自动审计结果，不等同于最终人工标注准确率。mask 连通域、3×3 边界和局部对比启发式可能产生假冲突，必须以人工复核结果作为最终版本。旧版队列曾将 111 条 presence 冲突送入人工审核；2026-08-19 修正后，这些记录自动拒绝，不再消耗人工审核。

## 4. 人工复核材料与填写方法

总工作簿：`outputs/gpt_attribute_audit_20260819_v2/manual_review_queue.xlsx`。

- `人工审核`：修订后推荐先检查 152 条，包含启发式抽样和部分客观冲突/不确定样本，不包含 presence 冲突。
- `完整人工候选`：排除自动拒绝后的全部人工候选，用于追溯；不要求第一轮全部检查。
- `自动拒绝`：111 条 presence 冲突，仅供追溯，不需要填写。
- `自动审计`：1,676 条自动字段结论。
- `字段汇总`：按数据集和字段统计。
- `枚举值`：人工填写允许值及含义。

人工操作：

1. 打开 `人工审核` sheet，从上到下检查推荐的 152 条。
2. 根据 `panel_path` 打开同名四联图：原图、增强图、GT overlay、目标放大图。
3. 只填写黄色列。各字段选择 `correct / wrong / uncertain / annotation_issue`。
4. 选择 `wrong` 时，在对应修正值列填写正确的结构化值；不确定时不要猜测。
5. 最终结论选择 `accept / partial / reject / annotation_issue`：只有关键字段均可信时才选 `accept`；部分字段可用时选 `partial`。
6. 保持样本 ID 和列名不变，保存工作簿后再生成过滤后的 `C_verified`、字段权重及反事实 `W`。

位置靠近 3×3 边界、目标过小无法判断形状，或背景语义证据不足时，应选择 `uncertain`。若 GT overlay 明显漏标、粘连或错位，应选择 `annotation_issue`，不要把问题强行归因于 GPT。

## 5. 后续门控

人工复核返回后再执行以下步骤：

1. 生成 `C_verified`：保留人工确认字段，错误字段替换为人工修正值，不确定字段 mask 掉；
2. 生成反事实 `W`：每次只改变一个已确认字段，记录改动字段与方向；
3. 缓存 `C/N/S/W` 的 token-level 与 global CLIP features；
4. 先运行 teacher 的 Phase B0，验证 `C` 相对 `N` 是否存在稳定增益、`C` 是否优于 `S/W`；
5. 只有 B0 通过预注册条件，才开始 Prompt→Mask 反事实增量蒸馏。

本轮自动审计不能证明文本 teacher 有效，只证明了哪些文本字段可以进入后续 teacher 实验、哪些字段必须降权或人工修正。
